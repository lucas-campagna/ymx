# 1.4 — Front-matter config & entry-path resolution

## Tasks

- [x] `CliOverrides { entry, from_keyword, default_keyword, max_depth, pretty, format, plain }` (all `Option`)
  - [x] `CliOverrides::default_for_tests()` -> all `None`
- [x] `extract_options(&Project, &CliOverrides) -> Result<Options, Vec<Diagnostic>>`
  - [x] Resolve entry: `cli.entry` or `"main.main"`; call `resolve_entry` -> entry `FileId` + qualified component (apply to `Options.entry` in entry-path form)
  - [x] Missing/ambiguous/malformed entry -> E009
  - [x] Look up that file's `raw_meta_ymx`; if absent -> engine defaults
  - [x] Validate each field present; unknown field -> E010; invalid value (non-int `max_depth`, bad `plain`, …) -> E010
  - [x] `plain` accepts `"false"` | `"true"` | `"template"` only; else E010
  - [x] Per-flag precedence: CLI override (`Some`) wins; else entry-file value; else engine default
  - [x] Non-entry `_ymx` blocks ignored entirely (never parsed)
- [x] Wire `plain` into namespace promotion (used by 1.6 resolver lookups):
  - [x] `Project` exposes a view of the effective global namespace given `PlainMode` (components only / templates only / none promoted from sub-namespaces)
  - [x] Promotion clash with existing global name -> E004 at extraction time (surface here since Options/plains are known)
- [x] Unit tests (inline projects): precedence table for each flag; E010 unknown field; E010 bad `plain`; E009 entry cases

## Acceptance

- [x] `extract_options` with empty `_ymx` + empty overrides == `Options::default()`
- [x] CLI override beats entry-file beats default, per field, independently
- [x] `plain: "maybe"` -> E010; `plain` valid values parse to `PlainMode`
- [x] Non-entry file with a malformed `_ymx` is NOT validated (no error)
