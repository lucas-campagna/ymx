# 1.33 — Shell execution stderr capture

## Goal

Add a `stderr` field to the `$sh`/`$pw` result object so callers can inspect
error output without merging it into stdout.

## Tasks

- [x] 1. Add `stderr: String` field to `ExecOutput` in `ymx-core/src/exec.rs`
- [x] 2. Update `StdExecutor` in `ymx-lib` to capture stderr (use `std::process::Command` with `.stderr(Stdio::piped())`)
- [x] 3. Update the resolver in `ymx-core/src/resolve.rs` to include `stderr` in the output object
- [x] 4. Update all existing test assertions to expect `stderr` field (empty string for most tests)
- [x] 5. Add test scenario `tests/cases/rule-19/stderr-capture/` — command that writes to stderr, verify it appears in `stderr` field

## Acceptance criteria

- [x] `$sh{echo hi}` returns `{exit_code: 0, stdout: "hi\n", stderr: ""}`
- [x] `$sh{echo err >&2}` returns `{exit_code: 0, stdout: "", stderr: "err\n"}`
- [x] `$sh{echo out; echo err >&2}` returns `{exit_code: 0, stdout: "out\n", stderr: "err\n"}`
- [x] Non-zero exit with stderr: `$sh{echo err >&2; exit 1}` → `{exit_code: 1, stdout: "", stderr: "err\n"}`
- [x] All existing tests pass (`cargo test --workspace`)
- [x] `cargo fmt --check` and `cargo clippy --workspace --all-targets` clean
