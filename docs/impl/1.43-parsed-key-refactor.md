# 1.43 — Introduce ParsedKey for property-key modifier parsing

## Task 1: Define ParsedKey and parse_property_key (ymx-core)

- [x] 1.1 Define `enum Suffix { None, Math, Call(String) }` and `struct ParsedKey { base: String, optional: bool, suffix: Suffix }` in a suitable location (e.g., resolve.rs or a new key.rs module)
- [x] 1.2 Implement `fn parse_property_key(raw: &str) -> Result<ParsedKey, Diagnostic>` that parses `x`, `x?`, `x$`, `x?$`, `x$abc`, `x?$abc`, `x$sh`, `x$pw` into the struct; rejects `$?` wrong-order as E010, `?` on invalid identifiers as E010
- [x] 1.3 Unit tests for parse_property_key covering all valid and error forms

## Task 2: Refactor resolve_property_set (ymx-core, resolve.rs)

- [x] 2.1 Replace the first loop's ad-hoc match arms (lines 1506–1706) with a single `parse_property_key` call + match on `ParsedKey` fields
- [x] 2.2 Replace the second loop's skip condition and key processing (lines 1802–1836) with ParsedKey-based logic — the skip is now implicit (keys with non-None suffix or optional flag are handled in the first pass)
- [x] 2.3 Refactor `reject_dollar_modifier_keys` (lines 1946–2009) to use `parse_property_key` instead of ad-hoc string checks

## Task 3: Refactor namespace.rs classify (ymx-core)

- [x] 3.1 Refactor `classify()` to use `parse_property_key` (or a variant for definition names) instead of its own strip_suffix chain; feed the result into `ComponentMeta`
