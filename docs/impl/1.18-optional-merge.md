# 1.18 — Rule 17: `?` optional/default-merge property-key modifier

## Tasks

- [x] Strip `?` from key name during parsing; record `<name>?: <default>` as a lazy default entry in the property set
- [x] During step 1 property resolution: if caller supplied `<name>` → skip default evaluation entirely; if absent → evaluate default lazily (interpolation, math, `$call()` resolved only at use-time)
- [x] `?` on integer keys (`0?:`) → default for positional slot `$0`
- [x] `?` on meta fields (`_ymx`/`_test`) or inside those blocks → E010 (unchanged from v1)
- [x] `$` modifier (rule 18) stays E010 in v1; wrong modifier order `x$?:` → E010
- [x] E010 for `?` on keys that are not valid effective identifiers
