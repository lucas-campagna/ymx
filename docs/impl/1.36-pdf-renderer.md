## 1. ymx-core: PdfBackend trait + system/bundled impls

- [x] `crates/ymx-core/src/render.rs` — add `PdfBackend` trait: `fn render(&self, html: &str) -> Result<Vec<u8>, PdfError>`
- [x] `PdfError` struct: `pub struct PdfError { pub message: String }`
- [x] `SystemChromeBackend` struct — uses `html2pdf` with `headless_chrome` (no fetch feature)
- [x] `BundledChromeBackend` struct — uses `html2pdf` with `headless_chrome/fetch` (auto-downloads Chromium)
- [x] Both impls: `render(&self, html: &str)` → `Result<Vec<u8>, PdfError>`
- [x] Feature flags in `crates/ymx-core/Cargo.toml`:
  ```toml
  [features]
  default = []
  pdf-system  = []          # opt-in: system Chrome (no fetch)
  pdf-bundled = ["fetch"]   # opt-in: auto-download Chromium (~150MB)
  ```
  `headless_chrome` and `urlencoding` are unconditional dependencies (always linked).
  `pdf-system` and `pdf-bundled` are additive gates that enable the backend implementations.
- [x] Re-export `PdfBackend`, `SystemChromeBackend`, `BundledChromeBackend`, `PdfError` from `crates/ymx-core/src/lib.rs`
- [x] Note: ymx-core stays I/O-free — trait takes `&str`, returns `Vec<u8>`
