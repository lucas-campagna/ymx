# 1.39 — External components via `_use` IPC declarations (core)

## Task 1: Core types — `IpcSpec`, `IpcRequest`, `IpcResponse`, `IpcError`, `IpcHost` trait, `Options.ipc` (ymx-core)

- [x] 1.1 Define all `IpcSpec` fields (runner, transport, protocol, request_template, reply_until, mode, on_request, parse, trim, error_pattern, envelope, stderr, on_response, on_error, startup_timeout, ready, request_timeout, stop_signal, stop_message, stop_timeout, before_start, after_start, before_stop, after_stop, prelude, url, method, headers, query, body, ok_status, addr, path, env, cwd, restart, max_restarts, lazy) and enums (IpcRunner, IpcTransport, IpcProtocol, IpcMode, IpcParse, IpcEnvelope, IpcStderr, IpcHttpBody, IpcRestart) in ymx-core
- [x] 1.2 Define `IpcRequest { args: Args }` and `IpcResponse { stdout, stderr, status: Option<u16> }` in ymx-core

- [x] 1.4 Define `pub trait IpcHost: Send + Sync { fn call(&self, name: &str, spec: &IpcSpec, request: IpcRequest) -> Result<IpcResponse, IpcError>; fn shutdown(&self); }` in ymx-core
- [x] 1.5 Add `pub allowed_ipc: Option<Vec<String>>` and `pub ipc: Option<Arc<dyn IpcHost>>` fields to `Options` struct in ymx-core
- [x] 1.6 Add `parse_ipc_spec(value: &Value) -> Result<IpcSpec, Vec<Diagnostic>>` function in ymx-core (called by ymx-lib during `_use` processing)

## Task 3: Resolver — IPC call evaluation (ymx-core)

- [x] 3.1 During property resolution (step 1 of rule 11), when a component lookup resolves to an IPC alias: render the call arguments per `mode` (text: $0 as string; json: args as {0:, 1:, name:} object)
- [x] 3.2 Build `IpcRequest { args }` and call `host.call(alias_name, &spec, request)`
- [x] 3.3 If `Options.ipc` is `None` → E018 (NoHost variant)
- [x] 3.4 If `allowed_ipc` is set and the transport is not in the list → E018 (DisallowedTransport variant)
- [x] 3.5 Map `IpcError` variants to E018 diagnostics with appropriate messages
- [x] 3.6 On success: apply response mapping (trim, parse per `parse`, error_pattern check, envelope: full adds stderr to result object)
- [x] 3.7 `on_request` hook: if set, call the named component with the full arg set; use its result as the outgoing string instead of `mode` rendering
- [x] 3.8 `on_response` hook: if set, call the named component with `$0` = raw reply; use its result as the final Value
- [x] 3.9 `on_error` hook: if set, call the named component on failure; if it returns a Value use it; if it throws/dies the original E018 stands
- [x] 3.10 Lifecycle hooks (`before_start`, `after_start`, `before_stop`, `after_stop`): invoke via `CommandExecutor` (rule-19 executor) at appropriate times; failure → E018 (HookFailed variant)
- [x] 3.11 `prelude`: send the string to stdin immediately after spawn, before waiting for `ready`
- [x] 3.12 `ready`: wait for the pattern on stdout/stderr before the first request is sent
- [x] 3.13 `restart: on-failure`: on IpcError during a call, mark the session dead; the next call respawns a fresh session
- [x] 3.14 Session management: lazy start (spawn on first call); session cached per (project root, alias, spec); session torn down on drop (stop_signal/stop_message/stop_timeout)

## Task 4: StdIpcHost (ymx-lib)

- [x] 4.1 Implement `StdIpcHost` in ymx-lib: manages process sessions keyed by (project_root, alias, spec)
- [x] 4.2 Process runner: spawn `cmd` (list or shell string) with `cwd`, `env`; connect stdin/stdout (and stderr for `pipe` + `read_from: stderr`)
- [x] 4.3 Pipe transport: write request to stdin, read reply per `protocol`/`reply_until`
- [x] 4.4 Line protocol: read one newline-delimited line as reply; trim trailing newline
- [x] 4.5 Sentinel protocol: read lines until `reply_until` regex matches; reply = all lines before the match (joined with \n)
- [x] 4.6 Raw protocol: read stdout to EOF (one-shot; closes stdin after write)
- [x] 4.7 Apply `request_template`: interpolate `$0`/`$name` per rule-19 scalar rendering, append to template
- [x] 4.8 Implement `startup_timeout`, `ready` wait, `request_timeout` per call
- [x] 4.9 Implement `stop_signal` / `stop_message` / `stop_timeout` teardown sequence
- [x] 4.10 Implement lifecycle hooks via `CommandExecutor` (rule-19 machinery)
- [x] 4.11 Implement `restart: on-failure`: mark session dead on error; respawn lazily on next call
- [x] 4.12 Session cache: `HashMap<(PathBuf, String, String), Session>` — key = (project_root, alias, spec_hash)
- [x] 4.13 `shutdown()`: drop all sessions (teardown per stop settings)
