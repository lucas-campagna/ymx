# 1.5 — Interpolation & math engine

## Tasks

- [x] String interpolation parser (`interp::scan`)
  - [x] `$name` (`[A-Za-z_][A-Za-z0-9_]*`), `$0`/`$1`/… (decimal), `${...}` (math, rule 7)
  - [x] Escapes: `\$` -> literal `$`, `\\` -> literal `\`; any other `\X` -> E010
  - [x] **Single-interpolation**: whole value is one `$name`/`$N`/`${...}` -> keep interpoland's native type (Int/Float/Bool/Object/Array)
  - [x] **Surrounding text**: result is String with each interpoland rendered per number->string rule
  - [x] Bool -> `"true"`/`"false"`; Null -> `"null"`; Object/Array into text -> E011
- [x] Shared number->string renderer (use `ir::render_f64` from 1.2)
- [x] `MathEngine` trait + v1 dynamic evaluator (`MathEngine::eval(src, &scope) -> Result<Value, Diagnostic>`)
  - [x] Lexer/parser for `+ - * / % **`, unary `-`, parens
  - [x] Precedence: `**` (right-assoc) > unary `-` > `* / %` (left) > `+ -` (left); NO comparison/equality/bool ops (they are literal text)
  - [x] Identifiers: bare (named arg / `last`); `$0`,`$1`,… (positional); `name(...)` component call (dotted namespace path allowed, e.g. `subdir.comp(...)`)
  - [x] `$letter` inside `${...}` -> E010; bare identifier not in scope & not `last` -> E003; NO component fallback for bare identifiers
  - [x] `+` semantics: both numbers -> numeric add (Float if either Float); both Strings -> concat; one String+number -> render number + concat; else E011
  - [x] `- * /` numeric only; `/` always Float; `/` by zero -> E011; `%` coerce both to Int (floats truncate toward zero, non-numeric -> E011), sign follows dividend
  - [x] `**`: Int**Int(non-negative) -> Int; else Float
  - [x] No quoted string literals in v1 (string operands come only from arg refs / re-scan)
- [ ] Math **operand resolution (String re-scan)**: a String-valued operand is re-parsed+evaluated as math in the current scope (incl. `last` & in-scope args); non-parseable -> left as String operand (`+` concat; numeric op -> E011). Document the gotcha (re-scan resolves bare-id-named string contents).
- [ ] `last` semantics: available only inside a reduce step (rules 13/16); referencing `last`/`$last` outside a reduce -> E003
- [ ] `${...}` return type: may be any Value; flows into interpolation per single/surrounding rule
