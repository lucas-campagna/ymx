# 1.47 — IPC commons lookup with `from`

## Task 1: Add `from` field to IpcSpec (ymx-core)

- [x] 1.1 Add `pub from: Option<String>` field to `IpcSpec` struct
- [x] 1.2 Set default to `None` in `Default` impl
- [x] 1.3 Add `"from"` to `KNOWN_FIELDS` array
- [x] 1.4 Parse `from` via `optional_string(map, "from")?` in `parse_ipc_spec`

### Acceptance criteria

- `from: sqlite3` parses without error and is stored in the spec
- Unknown `from_xxx` fields still raise E010

## Task 2: Implement commons lookup + merge in load_project (ymx-lib)

- [x] 2.1 When processing IPC declarations, if `spec.from` is `Some(name)`:
  - Load `~/.config/ymx/commons.yml` (create empty file if absent)
  - Parse it as a YMX document and find component `name`
  - If file missing → `E010`; if component not found → `E002`
- [x] 2.2 Deep-merge commons component fields with the override spec fields (override wins)
- [x] 2.3 Remove `from` from the merged spec
- [x] 2.4 Validate the merged spec (unknown fields, E010) before registering

### Acceptance criteria

- `_use: {db: {from: sqlite3}}` inherits all fields from `commons.yml`'s `sqlite3`
- Override fields replace commons fields
- `from` is not present in the final registered spec
- Missing commons file → E010; missing commons component → E002

## Task 3: Create commons.yml with starter templates (examples/)

- [x] 3.1 Create `examples/commons.yml` with 2-3 useful templates:
  - `sqlite3`: cmd `[sqlite3]`, transport pipe, protocol line, mode text, parse none
  - `curl`: cmd `curl`, shell true, transport pipe, protocol raw, request_template `"-s $0"`
  - `bash`: cmd `[bash]`, transport pipe, protocol sentinel, request_template `"{$0}\n__DONE__\n"`, reply_until `^__DONE__$`
- [x] 3.2 Create `examples/commons-usage.yml` demonstrating the feature:
  - `_use: {curl: {from: curl}}` — inherits curl template
  - `main: $curl{http://example.com}`
