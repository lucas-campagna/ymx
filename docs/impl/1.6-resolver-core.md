# 1.6 — Resolver core (rules 1–11)

## Tasks

- [x] `compile_component(project, component, args, opts) -> Result<Value, Vec<Diagnostic>>`
  - [x] `component` bare (global, `plain`-promoted) or dotted `subdir.comp`
  - [x] `compile` convenience: resolve `opts.entry` path -> qualified component + no args
- [x] Rule 1–2: components are callable; arg binding
  - [x] Named args bind `$name`; positional bind `$0`,`$1`,…
  - [x] Integer property key `0`,`1`,… denotes slot `$N` (string `"0"` is ordinary) — rule 4
  - [x] Bare `$name`: (a) named arg in scope -> value; (b) regular component `name` -> call w/ no args; (c) else E003 (rule 10)
  - [x] `$name(...)` unconditionally calls component `name` (bypasses arg lookup)
- [ ] Rule 3: inline `$name(...)` / `name(...)` math call
  - [ ] Call-site grammar: positional + named `k=v`; positional after named -> E012; `()` no args
  - [ ] Argument value parsing: Null/Bool/Int/Float/String; nested `$call()`,`${...}` as nested call-sites
  - [ ] Array/object literal as direct arg -> E013
  - [ ] Call target = single effective identifier (namespace-local); cross-namespace via math dotted form or `from`
- [ ] Rule 11 step 1 — property resolution (bottom-up)
  - [ ] Nested call-site = object w/ `from`, or value with `$comp()`/`${...}`; resolve deepest first, bubble up
  - [ ] Run inline `$comp()` and `${...}` BEFORE templates
  - [ ] (v2 hook) strip `?`/`$` key modifiers; `$`-suffix wraps in `${...}` (no-op in v1; modifiers rejected? — v1 ignores `?`/`$` modifiers? **Confirm**: v1 parses keys without modifiers; modifier presence is a v2 feature. Land parser flag here.)
- [ ] Rule 5 — template chain (step 2, namespaced + plain)
  - [ ] Lookup `$a` in calling component's namespace then global (per `plain`); broken link stops chain (no skip to `$$a`)
  - [ ] Template name (leading `$`) not a valid `from` target
  - [ ] Each link is a normal component call (own 3-step flow); first link may use rule 12/13/14 if `$template` is array (hooked in 1.7)
  - [ ] **Arg passing between chain steps**: scalar result -> `$0` overwrite (init retained); object result -> overwrite only returned keys for the immediately-next step then revert to initial; array -> mixed-shape (E010 for non-array link in a mixed chain) — rules 12–14 govern arrays (1.7)
  - [ ] Mixed-shape chain (array link in non-array chain) -> E010 when reached
- [ ] Rule 6 — `from` dispatch (step 3)
  - [ ] `from` value computed in step 1 (may be expression resolving to a name)
  - [ ] Valid regular-component `from` -> call target w/ rest of props (exclude `from`); suppress rule-8 shortcut
  - [ ] Invalid `from` (template target, non-String, missing) -> `from` is plain forwarded property; shortcut fires normally
  - [ ] Namespace-qualified `from: subdir.comp` supported
- [ ] Rule 8 — shortcut (step 3, sugar for `from`, mutually exclusive)
  - [ ] Property name matches a regular component -> call it w/ `value as $default`, rest as args
  - [ ] Multiple matches -> E006 (ambiguous shortcut)
  - [ ] Suppressed when valid `from` present; NOT suppressed when `from` invalid (from forwarded alongside)
  - [ ] Matches **regular** components only (not templates)
- [ ] Rule 9/10 — unknown props ignored; referenced (non-`?:`) props required -> E003
- [ ] Depth cap: check `depth == max_depth` on entry to each recursive op (inline call, math call, bare-`$name` fallback, template step, `from` dispatch) -> E008; else `depth += 1`
- [ ] (`?:` / `$` modifiers and rule 17/18 are v2 — parser must NOT accept them in v1; encountering them is a parse question — confirm in 1.3/1.5. Spec lists them as v2.)
