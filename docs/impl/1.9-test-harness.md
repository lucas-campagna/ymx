# 1.9 — Test harness (ymx-test)

## Tasks

- [x] `TestArgs { None, Named, Positional, Scalar }`; `Expected { Value(Value), Error { code } }`
- [x] `Test { target, args, expected, file: FileId, span: Span }`; `TestResult { test, actual: Result<Value, Vec<Diagnostic>>, passed }`
- [x] `parse_tests(&Project) -> Result<Vec<Test>, Vec<Diagnostic>>`
  - [x] Top-level `_test` shapes: bare A (scalar, targets entry), bare B (map w/ `result`|`error`, targets entry), type-2 map, list-of-type-2
  - [x] Disambiguation: top-level map w/ `result`/`error` key -> bare B; else type-2; top-level list always shape 4
  - [x] B variants: value `{args,result}` / error `{args,error}`; missing both / having both / non-string `error` -> E010 (malformed `_test`)
  - [x] `args` optional (absent = no args); shape mirrors call-site grammar (map/list/scalar)
  - [x] `args` values taken **literally** (no interpolation at parse time)
  - [x] Same-document targeting: each type-2 key must be defined in same doc as `_test` -> else E002; emit dotted form for sub-namespace targets
  - [x] bare A/B targets the project entry (`--entry` path / `main.main`)
  - [x] List-wrapping escape for targets named `result`/`args`/`error`
- [x] `run_tests(&Project, &Options) -> Vec<TestResult>`
  - [x] Per test: compile target w/ args under opts -> `actual`
  - [x] `Expected::Value`: passed iff `Ok(v)` with `v == expected`
  - [x] `Expected::Error`: passed iff some diagnostic from the compile has `code == expected.code` (post-load codes only; load-time codes never reachable since project already loaded)
  - [x] `passed` flag set accordingly
- [x] Integration harness: Rust test that walks `tests/cases/rule-NN/<scenario>/`
  - [x] `load_project` -> `extract_options(default_for_tests, plus scenario overrides)` -> `parse_tests`+`run_tests`
  - [x] Assert every test `passed`; print failing target + expected/actual diff
  - [x] A scenario is a FAIL if load or parse_tests errors (no `_test`-driveable load-time codes)
- [x] Unit tests (inline YAML) for unreachable-by-construction diagnostics: malformed `_test` (E010) and host-doc E001 (exercised via crate `#[test]`)

## Acceptance
- [ ] A trivial scenario (`main.yml` w/ `_test`) passes via the harness
- [ ] `parse_tests` rejects malformed B mappings (E010) with unit tests
- [ ] Cross-document target -> E002
- [ ] `Expected::Error` matches by code only
