# 1.31 — Component calls in shell interpolation

## Goal

Allow `$name(args)` inside `$sh{...}`/`$pw{...}` command strings to call a
component and interpolate the result as a string before shell execution.

## Tasks

- [x] 1. Add `Segment::Call { name, args, span }` variant to `interp::Segment`
- [ ] 2. Extend `scan()`: after `$name`, if next char is `(`, parse parenthesized arg list (same grammar as math `name(...)` calls in `MathEngine`); otherwise existing `$name` arg interpolation
- [ ] 3. Extend `resolve()`: for `Segment::Call`, resolve each arg against scope, call component via the registered `CallHook`, render result to string via `render_into_text`
- [ ] 4. Depth cap: component calls inside shell context consume depth slots (same as math calls)
- [ ] 5. Add test scenario `tests/cases/rule-19/shell-component-call/` — positional args, named args, no-arg call, unknown component (E002), non-scalar result (E011)

## Acceptance criteria

- [ ] `$sum(1,2)` inside `$sh{...}` calls `sum` with `$0=1, $1=2` and interpolates the result
- [ ] `$sum(a=1,b=2)` inside `$sh{...}` calls `sum` with named args and interpolates the result
- [ ] `$sum()` inside `$sh{...}` calls `sum` with no args
- [ ] Bare `$name` (no parens) still resolves as argument interpolation (no regression)
- [ ] Unknown component name → E002
- [ ] Non-scalar return value → E011
- [ ] Component calls consume depth slots (E008 at max depth)
- [ ] All existing tests pass (`cargo test --workspace`)
- [ ] `cargo fmt --check` and `cargo clippy --workspace --all-targets` clean
