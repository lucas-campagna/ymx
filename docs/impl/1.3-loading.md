# 1.3 — Project loading & namespace resolution

## Tasks

- [x] `ymx-core::parse` — parse one document string into a spanned AST/value tree
  - [x] Reject multi-document streams `---` (E001), complex mapping keys (E001), merge key `<<` (E001)
  - [x] Resolve YAML anchors/aliases; ignore explicit tags (`!!str`, …)
  - [x] Preserve line/col span on every scalar (for diagnostics)
  - [x] Record top-level scalar/array/object shapes for component bodies
- [x] Namespace model
  - [x] Global namespace = union of non-`_` defs across root files
  - [x] Sub-namespace per subdirectory (relative dotted path)
  - [x] Lexicographic load order
  - [x] Duplicate name in same namespace -> E004
  - [x] Builtin-name effective identifier (`map`/`reduce`/`merge`) -> E007 (any `$` count)
  - [x] Leading-`$` variant of `_ymx`/`_test` (`$_ymx`, `$$test`, …) -> E015
  - [x] `_`-prefixed effective identifier -> file-scoped (excluded from namespace merge)
- [x] Meta-key handling (raw, uninterpreted)
  - [x] Strip bare `_ymx`/`_test` from namespace; store raw `Value` on `Project.raw_meta_{ymx,test}` keyed by `FileId`
  - [x] Bare meta keys are consumed (no component registered); leading-`$` variants rejected (E015)
- [x] `ymx-lib::load_project(root: &Path) -> Result<Project, Vec<Diagnostic>>`
  - [x] Walk directory recursively (`.yml` + `.yaml`); assign `FileId` per file; populate `Project.files`
  - [x] Carry resolved `PathBuf` on every diagnostic (so load-errors render without a Project)
  - [x] All-or-nothing: collect all load diagnostics; if any -> `Err(diags)`
- [x] Entry-path resolution helper (`resolve_entry(&Project, &str) -> Result<(FileId, namespace, &str component), Diagnostic>`)
  - [x] Parse `<folder.path>.<file>.<component>`; require >=2 segments (else E009)
  - [x] Penultimate segment = file stem; both `.yml`+`.yaml` -> E009 (ambiguous)
  - [x] Resolve file under `<folder>/`; missing -> E009; component not defined in that file -> E009
  - [x] Returns the component's namespace-qualified path (`<folder>.<comp>`) + front-matter `FileId`
- [x] Namespace-qualified lookup (`resolve_ref`) used later by resolver/from/builtins
  - [x] Bare name -> global namespace (with `plain` promotions applied — wiring in 1.4)
  - [x] Dotted `subdir.comp` -> sub-namespace
  - [x] File-soped `_`-prefixed ref from another doc -> E005 (enforced at call site in 1.6)

## Acceptance

- [x] Unit tests (inline YAML) for: E001 multi-doc, E001 merge key, E004 duplicate, E007 builtin name, E015 `$_ymx`, file-scope exclusion

- [x] Unit test: `resolve_entry("a.b.c")` resolves to `a/b.yml` + component `c`; ambiguous stem -> E009; 1-segment -> E009
